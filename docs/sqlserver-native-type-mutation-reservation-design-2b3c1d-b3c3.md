基準 `b16cf62a5330d62f21c9d610e7fac92e12654f96`；開工 PR #66 為 Draft、未 Merge，CI #879 成功。僅新增本文件，靜態追查具名 SQL、Migration/Index/FK；沒有修改 [C2 原型](../server/src/modules/dataset/nativeTypeAcquisitionPrototype.ts)、正式 Writer、Schema 或執行資料庫測試。

**結論：正式 Mutation／共同 acquisition 仍 BLOCKED。** 下列為可供後續合成契約驗收的設計，不是已實作的 mutation executor／reservation。沿用 [C1 owner/G](sqlserver-native-type-common-acquisition-design-2b3c1d-b3c1.md)、[B3-B3 鎖圖](sqlserver-native-type-writer-lock-contract-2b3c1d-b3b3.md) 與 [C2 限制](sqlserver-native-type-acquisition-prototype-2b3c1d-b3c2.md)；`authority=NONE, runtimeBindVerified=false, deliveryAllowed=false, persistence=NOT_PROVEN` 不變。

## 1. Mutation 與 Union Reservation 契約（未實作）

未來 command 只能提供明示的意圖：固定 writer/operation、target identities、desired field/set delta、expected revisions、requestId；不能提交被當作權威的 Current/Proposed Scope、complete 或 allow-any-change。限域 backend 從精確 current snapshot 及固定業務規則驗證意圖，再計算 Expected Post-State；未知欄位、未知 writer/predicate、未能解析的間接變更／FK effect 拒絕。

定義 `C`＝Gate 後、prelock 保護並重新驗證的 Current；`Δ`＝驗證後的明示 mutation；`E=Apply(C,Δ)`＝Expected Post-State；`U=Closure(C) ∪ Closure(E) ∪ Reservations(Δ) ∪ RequiredSideEffects`。Closure 必含正／反向關聯、空 predicate、actor/role/permission、Source/lookup、policy、history/audit 與 FK/cascade 影響，不能只是 C2 的 12 種合成 nodes。刪掉最後一筆關聯後，**舊 ROW/RANGE 仍留在 U 並持鎖到結束**，不因 Post-Scope 變小而提早釋放。

交易前 discovery 只產生無權威 hint，含 current 及意圖可能涉及的 proposed parents／自然鍵／空範圍。唯一 owned SERIALIZABLE owner 設 XACT_ABORT，先取得 G，再以 C1 順序取得整個 U：AE guard→Permission/Role/grants→AppUser/membership→Source→精確排序 Dataset→Parameter/policy→Query/artifacts→Dashboard→source/layout→ACL→Review/Decision/Audit。Gate 後以受保護資料重算 C、E、U；與 hint 不符、缺 reservation、發現新早順位資源即**整筆 abort、釋放後重新 discovery**，不得在舊 tx 補鎖。所有 ID/版本精確字串，不經 Number；composite/natural key 不可用 C2 單一 BIGINT ordinal 代替。

自然鍵 reservation 依 DB 真正的 NVARCHAR 型別、collation、索引等值語意及完整前綴 predicate，包含不存在的 key；不以 JS trim/upper/hash 猜測大小寫、重音或尾空白等價。UQ 只能拒絕重複，不代表已鎖住 gap；range mode、索引路徑與 phantom 保護均待實機。G 是合作式協定，不能代替外部 DBA/舊 worker 的權限阻斷或強制 epoch。

### Identity 尚未分配

新 AppUser/Role、Parameter、Dashboard/Source row 在 E 使用**受限 Symbolic Identity slot**，綁定精確自然鍵或 parent/key predicate、型別、預期列數及允許的後續 FK，不接受 caller 指定猜測 ID。slot 不是資料庫 ID、授權或正式 evidence。

只可在對應 entity stage INSERT，將 SQL OUTPUT **於 SQL 層即轉精確字串**的單列 ID 綁到 slot；同 owner 以同自然鍵重讀驗證身份，再供已 reservation 的較後順位 membership/source 使用。不可假設 Identity 一定大於已鎖 IDs（reseed/restore/cache/gap 均需驗證）；若自然鍵 gap 不足涵蓋新增 PK/FK FIRST acquisition，需另審同 entity stage 的完整 key-space reservation／受控預分配。**目前無此證據，Identity 路徑 BLOCKED**，不能藉「INSERT 自然會鎖新列」跳過共同順序。分配後出現任何未保護的早期 scope，整筆 abort；rollback 不保證重用／回復 Identity seed。

**Union 範例**：Query `q=20` 從 Dataset `A=10` 換到 `B=9007199254740993`；A 仍有 Query 21、B 仍有 Query 22，B lookup 指向 11。U 的 Dataset 為 `[10,11,9007199254740993]`、Query 至少 `[20,21,22]`，加各 Parameter/反向 lookup predicates、Source、引用 q 的 Dashboard/ACL 與必要 artifacts。E 只容許 q 的 binding A→B、原規則的 unpublish/history 及已列 AE/Q receipt；A 的 Query 集合可少 q、B 的可多 q，但仍保留兩個 RANGE 到結束。若 Gate 後發現 B 另有新 lookup 12、Query 23 或新 Dashboard 引用，不能當「B 已在 Proposed」直接放行，必須 abort 重新 discovery。

**已確認的 production/C2 語意 GAP**：[managed service](../server/src/modules/dashboard/dashboardQuerySources.service.ts#L192) 既有 row 寫入 `datasetId: saved.datasetId`，只有新 row 取 validateQuery 回傳 Dataset；[repository UPDATE](../server/src/modules/dashboard/dashboardQuerySources.repository.ts#L119) 不改 DatasetId，service 輸出也將它視為 history。故既有 managed source 換 Query 後，stored DatasetId 可不同於 effective Query.DatasetId，並非可自行「修復」的值。pending conversion 仍要求 stored/effective 相符、已有 approval/layout reference 等仍按原 guard 拒絕。C2 將兩者強制相等的合成 schema 無法表達這些語意；未來規格須分別保留 historical-D／effective-D 邊與原拒絕條件，U 取兩者 union，不改 C2、不藉關閉一致性檢查冒稱已相容。

## 3. Predicate／Index／FK Matrix

下列 **COVERED 只指 Migration 來源明示某 key／FK 及可用前綴**；GAP 指來源未找到符合該方向的索引／契約；實際部署 Catalog、index enabled/trusted、collation、trigger、execution plan、key-range／escalation 全為 UNKNOWN，無正式通過者。SQL Server 不會因有 FK 自動建立支援所有反向 predicate 的索引。缺索引不等於 SERIALIZABLE 必不保護 phantom，但也不能推定掃描範圍、吞吐及 deadlock 行為可接受。

## 4. 正確的 Mutation／CAS／Final Revalidation

[C2](../server/src/modules/dataset/nativeTypeAcquisitionPrototype.ts#L290) 的 FINAL_REVALIDATE 重算原圖並要求與原 Hint 相等，MUTATE 只有 staged marker、modelRevision 只在 ledger 推進；它會拒絕真正合法改綁，也沒有自然鍵／symbolic Identity／composite reservation。**保持 C2 原樣，不刪 scope 比對來讓 mutation 通過**；後續需另定版本的 expected-state 契約。

候選流程：① 交易外資料只作 hint，推導無權威候選 C0/E0/U0 並檢查意圖格式；② O/G 依 hint 取得完整 U0/reservations；③ owned exact reader 重新計算 C/E/U，須與 hint 的身份／版本／完整集合一致，才驗 actor/token/scope、業務前置與 expected AE/Q/D/S；④ CAS affectedRows 恰等於已列目標數（single-row 必 1）並執行唯一 Δ；⑤ 以 own DML receipts 綁定新 ID／DB-generated revisions；⑥ 重新獨立讀取 Actual Post-State `P`，驗 `P == E[bound slots]`，且全部讀寫／predicate 仍在 U；⑦ 最終授權、版本、mandatory audit/Decision 契約重驗後才 commit。正式取證讀寫同一已驗證 owner，交易外 hint 不授權；任一步不確定全體拒絕。

E 必須是後端對 C＋固定 operation 規則的確定性轉換，**不是拿 P 回填 E**。允許未知的 DB-generated slots 只限預先列出的 Identity/RV/必要時間等欄位、型別、來源 request/row 與列數；不可 wildcard 任意新 row／新 lookup／新 permission。預期 cascade/SET NULL、history、unpublish、token/evidence 改變要明列；trigger 多做一筆即 unexpected drift。自己的 operation/column/affected-row inventory 也必須匹配 Δ，不能因最終 set 相同而忽略額外 delete/reinsert；沒有可驗證版本／寫入紀錄的往返仍 BLOCKED。receipt 只作當前交易內關聯，不自行構成 durable proof。

Final 同時檢查：新增／刪除 row 是否恰為 Δ；刪後空 predicate 是否恰為 E；未觸及 ROW、range members、policy、artifact 身份／版本保持；自己修改的版本須等於 own 精確 receipt、不得預測 SQL ROWVERSION 的下一個值或採信 caller；未預期的新 version／member 即 abort。A→B→A 即使內容恢復仍需真正 mutation epoch／incarnation 失效，digest 和 C2 synthetic predicate revision 均不能防 production ABA。真實 range revision／catalog generation 與 Q 尚未建立，無法藉本文件宣稱已驗證。

合法 Δ 不豁免授權重驗：actor/reviewer 的當前 permission/token/scope、SYSTEM_ADMIN/last-admin、ACL、遮蔽／患者／Dashboard guards 仍逐一驗證，不可因「新 AE 是自己的」直接放行。自撤銷／刪自己等可能使 actor post-state 失權的情況，需另審既有語意與安全線性化規則；未驗證先 BLOCKED，不能藉停用 final auth check 解決。

1205/1222、Gate negative/ownership lost、CAS conflict、未知 scope／reservation、rollback failure 或 commit unknown 均不回成功。commit unknown 可能全有或全無：保留 unknown/quarantine、透過未來持久 RequestId/Decision/Audit 精確 Reader 查核，不假定 rollback、不盲重播同鍵。Identity/版本／audit receipt 不能代替持久性。G 也不能阻止不遵守協定的 DBA、直接 SQL、舊 worker 或跨 DB DDL。
