## 動態 SQL、安裝與測試邊界

- 917～921／926 以 EXEC／sp_executesql 分批編譯新欄位；清冊將字面 SQL 解開再核對，不因外層字串漏掉物件。
- 923 的 DDL 由 datasetMetadata923Catalog.ts `render923Draft()` 產生；已離線逐 byte 核對與 tracked draft 相同。installer 使用 renderer，不讀不存在的 migrations/923 SQL。
- 924 installer 只使用既有完整基線與專用 draft，exact Catalog＋明確目標；其過去基線 gate 不等於允許在含 926 的環境重跑。
- 925 `displayDdlUrl` 同時被專用 installer 與 Runtime schema validator 使用。打包流程複製到 payload/database 與 tools 路徑是部署相容路徑，不是兩份可任意刪除的 repository DDL。
- `migrate.ts status` 在讀狀態前可能 bootstrap Schema/Ledger，**不是保證唯讀**；本次沒有執行 status、adopt、apply、installer 或 DB acceptance CLI。
- fixture／ephemeral acceptance 在隔離 DB 建立同名表或錯形表，驗證 reject／rollback；不代表正式 DDL 重複。f3.Records／FenceState／ControlledDdl 為 Source Fence 隔離測試物件，ACTIVE（測試用途），不列入正式目標物件總數。
- `PK_DatasetSecurityScope` 被 dataset923ScopeConfirmationGate 明確 INDEX hint 使用。改名／合併前必須同時處理 hint、Catalog 與並行鎖定，不能僅比鍵前綴。
- CI 一般工作包含 Server／Client／Browser／Windows／SQL smoke／disposable lifecycle SQL。923、924 full-schema、Windows installer、release bundle 工作限制 PR #66；PR #83 的一般 CI 綠燈 **不代表** 923／924／925 全 Schema 實際相容驗收。
