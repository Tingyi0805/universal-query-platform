# 患者清單曝光與個別病歷查看稽核規格

## 事件定義

- PATIENT_LIST_DISCLOSED：伺服器已向特定登入 Session 回傳患者清單；**不代表人員實際逐筆閱讀**。
- PATIENT_DETAIL_VIEWED：使用者成功取得單一患者詳細資訊。
- PATIENT_RECORD_VIEWED：取得患者檢驗、影像、報告等特定病歷類別。
- PATIENT_DATA_EXPORTED：下載或產生含患者資料的匯出檔。
- PATIENT_LIST_REFRESHED：自動更新資料；須標示系統更新，不可偽裝成使用者主動查看。

## 建議實作流程

1. 在每個含患者清單的資料集上，由管理員設定患者識別欄位（不可由欄位名稱猜測）；沒有設定時不應聲稱可追溯到個別患者。
2. 在**伺服器回傳資料的時點**寫入一次曝光主事件，記錄使用者、工作站、Session、資料集、頁碼、筆數、手動／自動、遮蔽狀態及欄位分類；不要記錄原始姓名、病歷號或查詢敏感參數。
3. 以機構保管的 HMAC-SHA256 金鑰，將標準化患者唯一識別碼轉為 PatientKeyHash，寫入關聯明細；不要使用無金鑰 SHA-256 雜湊病歷號（容易遭字典猜測）。
4. 僅紀錄實際回傳的分頁資料，不能把整個查詢結果集都算成已曝光。
5. 詳細頁面另記 PATIENT_DETAIL_VIEWED，不可用清單曝光事件取代。
6. 自動輪播／刷新以裝置身分記錄，不要推定有某位員工親自閱讀。
7. 稽核寫入失敗時，患者資料回應應依醫院政策採取 fail-closed 或可靠佇列持久化；不可僅記錄警告後無條件放行。
8. 對事件與患者關聯設定權限、保存期限、查詢稽核與資料庫存取控管；稽核報表需區分「清單包含患者」與「點開患者」。

## 目前實作界線

Migration 906 僅建立可供稽核的資料表結構，**尚未接入實際查詢回應路徑**，不能宣稱已開始追蹤患者清單。後續須依資料集設定患者識別欄位、實作 HMAC、整合查詢服務及測試。
