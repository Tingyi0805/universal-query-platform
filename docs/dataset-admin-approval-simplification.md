# UQP Dataset 操作介面簡化：管理者核准使用／播放（2026-11-18）

## 使用者決策
- Dataset 設計頁不再要求一般管理者操作「Dataset 患者揭露稽核設定」及「Dataset 敏感資料欄位管理」兩套複雜介面。
- 改成單一「使用與播放核准」區塊，讓具管理權限者決定能否讓登入者查詢、能否在 Dashboard 公共畫面播放。
- 現有 `C:\UQP`、Port、`UniversalQueryPlatform`、登入、IIS、RJDB 與資料不因 UI 簡化而改變。
- PR99 CHART 的 Gate 及未授權 CREATE／公共播放仍保持 OFF，不能由 Dataset 核准繞過。

## 目標介面（需要實作，不代表目前已存在）
Dataset 設計：資料來源、SQL、參數、預覽 + 「使用與播放核准」

| 核准用途 | 預設狀態 | 管理者操作 | 仍必須符合的執行條件 |
|---|---|---|---|
| 登入後使用（Query） | 未核准 | 核准使用／停止使用 | 原 JWT / TokenVersion / Query Published / User ACL / Dataset Active / 遮蔽及操作稽核 |
| Dashboard 公共播放 | 未核准 | 核准播放／停止播放 | 原公共顯示政策、可信欄位、隱私遮蔽、患者揭露稽核、裝置 Token / IP / 來源分頁／Query-only 安全檢查 |

介面顯示狀態：未核准／已核准／原始定義異動需重新核准／安全條件尚未具備。
每筆決策顯示操作者、時間。敏感規則／稽核狀態僅顯示「安全檢查通過／尚未就緒」和可理解原因，不展示大量規則表單。

## 非刪除事項（強制）
1. **刪除的是一般頁面的複雜操作介面，不刪 DB 資料、稽核紀錄及既有遮蔽規則**。既有已設定遮蔽持續生效。
2. 後端資料交付、患者揭露稽核不可關閉或略過；公共播放預設不得傳輸未審核敏感欄位。不得以管理者點擊代替必要的識別鍵／遮蔽證據。
3. 如果既有政策未完成、925 相關 Schema／功能旗標未具備、資料定義或來源／遮蔽版本變動，核准動作**必須拒絕或標為待重核**，而非直接放行。
4. 不使用前端 `isApproved` 判斷做安全授權；所有核准必須由 Server 在實際交付時驗證，依資料庫可信狀態實施權限控制。
5. 撤銷核准需即時對新查詢與播放請求生效，包含稽核紀錄；發出請求時和傳輸前應再次驗證。
6. 允許的 Query 及公共播放是**兩個獨立授權**，不能相互推導，CHART release Gate 更不能推導。

## 目前 UQP 已有可重用基礎
- `uqp.Dataset.IsActive`、Query Publisher `Published` / Query ACL 做登入者查詢可用性（但未必等同管理者核准，需要權限封裝）。
- Dataset `/public-display-policy` 支援帶版號的明確確認、指定允許欄位、可信遮蔽規則與不可變稽核；仍受 `DATASET_PUBLIC_DISPLAY_MANAGEMENT` 關閉預設限制。
- Dashboard query-only、裝置與公共來源安全檢查；不得放寬。
- 患者揭露稽核、Dataset 遮蔽策略在 Server 交付流程中運作。

## 最少修改的實作驗收界線
- 前端：用單一核准面板替代兩個密集表單；無管理權限者僅顯示狀態；核准／撤銷各需確認；錯誤不變更顯示授權狀態。
- 後端：必要時新建 admin-only decision contract，具 live user permission、版本 CAS、Audit 同交易、預設拒絕；嚴禁僅用現有 UI checkbox 切換前端放行。
- DB：優先沿用既有 925 公共政策與 Dataset／Query 狀態，不要自動新增 Migration；如現有 Schema 無法完整表達管理者核准，需獨立評估最小 Schema 而非弱化原機制。
- 回歸：已核准／未核准／撤銷／來源異動／權限撤銷／新敏感欄位／患者稽核缺失／裝置拒絕。以最小受影響案例測試，復用既有 PR99／PR100 成功證據。
- 交付：與正在測試的 PR99+100 V2 分開，不更動已部署 `C:\UQP`。完成安全核准邏輯與 CI 之後才製作新的原環境覆蓋測試 ZIP。

## 狀態
管理者用途核准的候選 UI/API 已於 PR #101 實作並進入 CI 驗證；未部署至 C:\UQP。Dataset 使用核准採 IsActive + 版本 CAS + 同交易 Audit，停止使用會取消關聯 Query 發佈。播放核准僅採已審查的敏感欄位策略與既有 925 寫入交易，無政策則拒絕；原公共顯示 PUT 寫入也要求目前有效的 MANAGE_USERS 身分。舊的 Dataset 編輯 PUT 不得更改 IsActive。仍須完成受影響的前端 E2E 及實際環境測試，不可宣稱正式通過。
