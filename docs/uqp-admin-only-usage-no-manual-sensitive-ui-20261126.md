# UQP 資料權限操作簡化決策（2026-11-26）

## 使用者核定的目標

- UQP Dataset 管理者只操作**核准使用／停止使用**。不再提供逐欄敏感分類、全部遮蔽／不顯示、遮蔽範本、患者欄位人工設定、Snapshot 手動發證，或 Owner／Reviewer 安全配置等額外 UI。
- 既有測試環境照舊：`C:\UQP`、埠 3200、原 `.env`、原資料庫、原 IIS `web.config`。採單一 ZIP 經 Hash 驗證後覆蓋，不另建實例。
- **不等於授權未遮蔽患者資料向無權限者、公共 Dashboard 或公開播放裝置交付**。必須保留 Server 授權、敏感個資的預設保護、請求稽核、登入與來源版本校驗以及四個播放 Gate。不要把空政策視為已確認、不要用「管理者核准」自動關閉患者揭露稽核。

## 落實範圍

1. Client 移除人工敏感欄位／患者稽核／範本草稿入口；只留下 Dataset 使用核准。可保留不讀資料列的欄位名稱／型別設計參考；不把候選欄位當安全確認。
2. 既有 Server 資料保護與稽核仍可供舊 Dashboard／Query 使用；人工敏感設定對外 API 的停用、資料庫清理及新「無人工欄位政策」交付契約須整體完成並測試，**不得只刪除保護資料表或跳過安全檢查**。
3. 新 Dataset 未有可信交付保護時仍拒絕預覽。後續預覽契約須改成「管理者 Dataset 使用核准 + 有效 RBAC + 必要的伺服端資料保護／患者稽核 + 即時來源版本」，再加測試證明新增／修改 SQL 不會自動放出未授權資料；公共播放保持單獨 Gate。
4. 目前 `DATASET_COLUMN_DESCRIPTION_DRIVER_FAILED` 已用固定診斷分階段提示，真實院內連線原因仍未知；到**資料來源管理**使用既有資料來源的「測試欄位描述（不取資料列）」取得代碼。重建 UQP DB 不是解決外部 DataSource Describe 的方法。

## 關於資料庫

**目前不重建、不 DROP、不 TRUNCATE、不自動刪除任何資料。** 先保存當前 `C:\UQP_Backup\PR99-PR100-before-20261126_093638` 安裝備份，同時進行 SQL Server 完整資料庫備份。注意更新腳本備份的是程式檔案，**不是 SQL Server 資料庫備份**。

如整合後仍須乾淨測試，應先完成並驗證適用於既有 schema 的一次性清理 SQL，區分要保留的帳號、使用者、角色、權限、系統設定、版本與稽核證據，及可清除的舊 Dataset／Query／Dashboard 測試內容。必須先備份、記錄資料庫名稱／身分核對、唯讀預覽刪除清單、取得使用者明確同意，才可進行實際刪除。不得把新建 DB 當作預設更新步驟。

## 驗收判斷

- **UI 移除成功 ≠ 完整預覽流程成功**；欄位描述、Server 輸出安全契約、Patient Audit、Dashboard Gate、資料庫清理分別標示實測狀態。
- 不重做已通過的「核准使用／停止使用」或既有 CI 測試，不無限擴大階段。
